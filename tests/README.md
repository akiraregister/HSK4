# テスト

`index.html` は約900KBの単一ファイルで、ビルドもフレームワークもありません。
そのぶん壊れたことに気づきにくいので、実ブラウザで画面を操作して確かめるテストを置いています。

実際にこれで拾ったバグの例：

- 削除した関数への `window.*` 代入が残り、起動時に全体が停止していた
- `const` の一時的死角で例外が出て、`catch` が握りつぶし機能が黙って無効化されていた
- イベント名がプロパティに上書きされ、計測ログに名前が残っていなかった
- ブックマークの格納形が違い、一覧が `b.id.match` で落ちていた
- 復習の離脱計測がボタン経由しか拾えていなかった
- ★や難易度を押すと `render()` が走り、Day学習の途中でミニテストとリスニングが
  最初からやり直しになっていた（4ステップ化のときに表面化。いまは該当箇所だけ更新する）
- 中文の要素（`.zh` `.vrow-zh` `.ex`）が和文書体の一覧にも入っていて後勝ちで上書きされ、
  簡体字だけの字が別の書体へ落ちて1つの文の中で字面が崩れていた
- 読み込んでいないウェイト（800・900）を24か所で指定しており、ブラウザが太らせて
  偽装していた（明朝は横画が細いのでつぶれる）
- 初回案内の状態クラスを素の `done` で書いたら、完了画面の `.done{text-align:center}` を
  拾って、畳んだ見出しが中央寄せになっていた（`intro-done` へ改名）。
  **1ファイルなのでクラス名は全部が同じ名前空間にある**
- その直しのときに `.intro-rows b` `.intro-rows span` の `display:block` ごと
  書き換えて消し、説明文が見出しと同じ行へ流れていた
- **聞くステップを抜けても音声だけ鳴り続けていた。** `dayNext()` / `dayPrev()` が
  `lsStopAudio()` を呼んでいなかった（`goView()` と `setDay()` だけが呼んでいた）。
  `tests/listen-test.mjs` を足すときに、わざと元へ戻して落ちることを確かめてある
- **読み上げボタンが薄すぎて、存在に気づかれていなかった。** 実機で「単語の音声は無いのか」
  と聞かれて発覚。機能があるかどうかはテストで見られても、**見えているかどうかは
  見られていなかった**（灯りの件と同じ抜け）。いまは罫で囲い、色と大きさも見張っている
- **炎の灯りが一度もついていなかった。** `filter:drop-shadow` を `clip-path` と同じ
  要素に置いており、SVGは filter → clip の順に適用するので光が切り落とされていた。
  テストは `prefers-reduced-motion` で `filter==='none'` を見るだけだったので
  素通りしていた（**「指定してある」と「見えている」は別**。実際に撮って気づいた）
- `build-content.mjs` でブロックを前から置換してしまい、後ろのブロックのオフセットが
  ずれて `index.html` の別の場所へ書き込み、ファイルを壊した（作業用コピーで発見。
  いまは降順に置換し、書き出す前に読み直して検算する）

## 動かし方

```bash
npm i playwright          # 初回のみ
node tests/run.mjs        # 全スイート（静的サーバーは自動で立ち上がります）
node tests/run.mjs nav lp # 指定したものだけ
```

Chromium が既定の場所に無い環境では、実行ファイルを指定します。

```bash
CHROMIUM=/path/to/chrome node tests/run.mjs
```

## 書くときの約束

- **本番にテスト用のフックを足さない。** モジュールスコープの変数は外から読めないので、
  画面に出ている文字（例：見出しの「模試 1 / 40」）から読み取ります。
- **セレクタは `#content` か `#settingsPanel` に限定する。** 設定パネルは常時DOMにあるため、
  `button:has-text("受ける")` のような指定が別画面のボタンに当たります。
- **アプリの起動を待つ。** 900KBあるので、遷移直後は3秒ほど見ておかないと取りこぼします。
