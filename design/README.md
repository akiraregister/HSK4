# アプリ改修案 — 分析とモックアップ

`design/index.html` を開くと、改修後の画面を実際に触れます。
**アプリ本体（`../index.html`）にはまだ一切手を入れていません。**
画面の形と流れを実装前に決めて、作り直しの無駄をなくすためのものです。

- 開いた直後は「改善案」が選ばれています。左上のトグルで「いま」（現行画面）と見比べられます
- ◧ が付いた画面（今日・学習・ミニテスト・設定）が比較できます。完了・無料の区切り・価格は新設なので比較対象がありません
- 改善案の側はボタンが動きます。今日 →「学習を始める」→「次へ」→「答え合わせ」と辿れます
- 色・書体はアプリと同じトークンを共有しています。新しい色は足していません

撮り直し：`node design/capture-current.mjs`
（現行画面を撮り直し、`design/index.html` の中へ data URI として埋め込み直します。
埋め込んでいるのは、**ファイル単体で開いても画像が出るようにするため**です。
Finderから開く・プレビューパネルで見る・メールに添付する、といった場合に
隣の `current/*.png` を読みに行けず、画像だけ欠けるのを防いでいます。）

## 1. 見つかった問題

全画面を実機サイズで撮り、課金まわりのコードを読んだうえでの整理。
**デザインの問題より先に「売り物として見せる設計」が抜けている**、というのが結論。

### A. マネタイズ（最優先）

| # | 問題 | 場所 |
|---|---|---|
| A1 | **価格がアプリ内に一度も出ない。** Day一覧の🔒をタップすると `startCheckout()` が直接走り、Googleログイン → Stripeへ飛ぶ。値段も中身も見ないまま決済画面に着く | `lockedDayHTML()` |
| A2 | **クーポン入力欄が購入ボタンより上にある。** 「割引があるらしい」と全員に気づかせ、コードを探しに離脱させる | 同上 |
| A3 | **購入前にログインが必須。** 未ログインだと即Googleポップアップ。最大の離脱点で、しかも中国からは到達しない | `startCheckout()` |
| A4 | **無料体験の終わりに何も起きない。** Day7を完了しても区切りもDay8の予告もない。paywallは壁ではなく予告であるべき | — |
| A5 | 単語タブが無料版では35語しか出ない。**498語すべて出して未購入分に🔒**を付けたほうが、教材の厚みがそのまま購入理由になる | `renderVocabScreen()` |
| A6 | 「購入済みの内容を確認する」が実質「購入を復元」。**設定に復元導線がない**ので、機種変・再インストール時に辿り着けない。失敗時は `alert()` | — |
| A7 | **模試と級診断が設定タブの奥。** 売りの2機能が最も見つからない場所にある | `renderSettings()` |

### B. 初回体験・継続

- **B1 初回起動がいきなり20問・約7分の級診断。** 価値を一度も見せる前に7分を要求している。最大の離脱点
- **B2** 診断中も4タブのヘッダーが出ていて離脱できる。オンボーディングは全画面で
- **B3** 今日画面で「まだありません」が Day 1 と同じ大きさ。初日の主役は1つだけにすべき
- **B4 連続日数も完了の手応えも無い。** 90日完走が商品なのに、続けた証が0%リングだけ
- **B5 リマインダーが無い。** iOS 16.4以降、ホーム画面に追加したPWAはWeb Pushが使える

### C. 情報設計・レイアウト

- **C1 ナビが三重。** 上に4タブ／Day画面の上に「前の日・Day選択・次の日」／下に「前・完了・次」
- **C2 ヘッダーが縦を約300px（画面の12%）食う。** 滅多に切り替えないタブが常時表示。モバイルの定石は下タブ
- **C3** Day画面は1本のスクロール。単語5→文法3→リスニング→テストが延々と続き、今どこで、あとどれだけかが分からない
- **C4** カードの入れ子が深く（カード＞カード＞カード）、枠線だらけで視線が迷う

### D. すぐ直せる粗

1. **ブックマークタブにDay画面の下ナビ（前・完了済み・次）が出ている。**
   `render()` が `bottomNav` を表示してから bookmark で早期リターンしているため。
   押すと関係ないDayの完了状態が変わる。実質バグ
2. 受験予定日が `mm/dd/yyyy` のまま（`<input type="date">` のロケール未指定）
3. 初回起動の「スキップして始める」がボタン内で改行する
4. ブックマークでピンインが二重に出ている
5. 決済まわりが `alert()`。アプリ内トースト（`hsk-toast`）があるのに使っていない

## 2. 3つの案と進める順番

| 案 | 中身 | 狙い | 規模 | リスク |
|---|---|---|---|---|
| **A 一画面一動作** | ナビ・情報の優先順位・学習のステップ化 | 迷いどころを消す。触れる状態にする | 小 | 小（CSSと描画の並べ替えが中心。SRS・データ構造は無傷） |
| **C 有料商品として見せる** | 価格画面・無料の区切り・復元導線 | 見ないまま決済画面に飛ぶ現状をやめる | 中 | 中（Worker/Stripe側も少し触る） |
| **B 習慣ドリブン** | ストリーク・通知・週次サマリー | 90日完走率を上げ、口コミと再訪を作る | 大 | 中（表示層を大きく作り替え。SWにpush追加） |

**A → C → B の順。** Aをやらないと、Cで作る価格画面もノイズの中に埋もれる。
Cは売上に直結し、Bは売れ始めてから効く。
今回のモックは **AとC**。Bは完了画面だけ先に受け皿として作ってある。

## 5. 案B — 今回はモックしていない

売れ始めてから着手する想定。完了画面（案Aで作る）がその受け皿になる。

- ホームを「今日の1枚」＋連続日数＋今週のカレンダーに寄せる
- 完了時の演出と週次サマリー
- **Web Push でリマインダー**（ホーム画面に追加したPWA向け。`sw.js` に push を足す）
- 学習を途切れないセッションとして流す（カードを送って進む）
- ストリークが途切れたときの体験も設計が要る（B4を入れるなら同時に考えること）

## 6. 実装するときの注意

- 画面遷移は必ず `goView()` を通す（`currentView` 1つで持つ設計）。新しい画面（完了・価格）も値を足して同じ経路に乗せる
- `LESSONS.length` ではなく `TOTAL_DAYS`（固定90）を使う。未購入だとDay8-90は存在しない
- 色は `:root` の既存トークンだけ。セージ／アプリコット／ブラッシュの3色で足りないか先に考える
- 丸ゴシック（Zen Maru Gothic）は見出し・ボタン・数字だけ。読ませる文章は Zen Kaku Gothic New
- **下タブへの変更は `tests/nav-test.mjs` が落ちる**（`.nav-tab` が4つあることを見ている）。テストも同時に直すこと
- 変更したら `node tests/run.mjs` を必ず通す

## 7. まだ決まっていないこと

1. **単語を1語ずつめくる形にするか。** いまの「5語を一覧」から変わるので好みが分かれる
2. **完了後に次のDayへ進ませない**設計にしている（1日1Dayが商品の形なので）。まとめて進めたい人向けの抜け道を残すか
3. **価格画面の比較表の項目。** いまは6行。増やすか減らすか
4. **ストリークを入れるか。** 入れると「途切れた」ときの体験も設計が要る
