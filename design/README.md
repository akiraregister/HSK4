# アプリ改修案 — 分析とモックアップ

`design/index.html` を開くと、改修後の画面を実際に触れます。
**アプリ本体（`../index.html`）にはまだ一切手を入れていません。**
画面の形と流れを実装前に決めて、作り直しの無駄をなくすためのものです。

- 開いた直後は「改善案」が選ばれています。左上のトグルで「いま」（現行画面）と見比べられます
- ◧ が付いた画面（今日・学習・ミニテスト・設定）が比較できます。完了・無料の区切り・価格は新設なので比較対象がありません
- 改善案の側はボタンが動きます。今日 →「学習を始める」→「次へ」→「答え合わせ」と辿れます
- 色・書体はアプリと同じトークンを共有しています。新しい色は足していません

撮り直し：`node design/capture-current.mjs`
（現行画面を撮り直し、`design/index.html` の中へ data URI として埋め込み直します。
埋め込んでいるのは、**ファイル単体で開いても画像が出るようにするため**です。
Finderから開く・プレビューパネルで見る・メールに添付する、といった場合に
隣の `current/*.png` を読みに行けず、画像だけ欠けるのを防いでいます。）

`design/directions.html` は**視覚デザインの方向**を4通り並べて比べるページです（下の「8. デザインの方向」）。
`design/directions-bold.html` は、いまの世界観を一度捨てて作った**大胆な3案**です（下の「9.」）。
`design/refined.html` は、方向を決めたあとの**仕上げ（洗練）の前後比較**です（下の「10.」）。
`design/x-next.html` は、**案Xで進める前提のアイコン候補と今日画面の改善**です（下の「11.」）。
`design/icons-flame.html` は、そのうち**炎（案5）を軸にした派生案**です（下の「12.」）。

## 1. 見つかった問題

全画面を実機サイズで撮り、課金まわりのコードを読んだうえでの整理。
**デザインの問題より先に「売り物として見せる設計」が抜けている**、というのが結論。

### A. マネタイズ（最優先）

| # | 問題 | 場所 |
|---|---|---|
| A1 | **価格がアプリ内に一度も出ない。** Day一覧の🔒をタップすると `startCheckout()` が直接走り、Googleログイン → Stripeへ飛ぶ。値段も中身も見ないまま決済画面に着く | `lockedDayHTML()` |
| A2 | **クーポン入力欄が購入ボタンより上にある。** 「割引があるらしい」と全員に気づかせ、コードを探しに離脱させる | 同上 |
| A3 | **購入前にログインが必須。** 未ログインだと即Googleポップアップ。最大の離脱点で、しかも中国からは到達しない | `startCheckout()` |
| A4 | **無料体験の終わりに何も起きない。** Day7を完了しても区切りもDay8の予告もない。paywallは壁ではなく予告であるべき | — |
| A5 | 単語タブが無料版では35語しか出ない。**498語すべて出して未購入分に🔒**を付けたほうが、教材の厚みがそのまま購入理由になる | `renderVocabScreen()` |
| A6 | 「購入済みの内容を確認する」が実質「購入を復元」。**設定に復元導線がない**ので、機種変・再インストール時に辿り着けない。失敗時は `alert()` | — |
| A7 | **模試と級診断が設定タブの奥。** 売りの2機能が最も見つからない場所にある | `renderSettings()` |

### B. 初回体験・継続

- **B1 初回起動がいきなり20問・約7分の級診断。** 価値を一度も見せる前に7分を要求している。最大の離脱点
- **B2** 診断中も4タブのヘッダーが出ていて離脱できる。オンボーディングは全画面で
- **B3** 今日画面で「まだありません」が Day 1 と同じ大きさ。初日の主役は1つだけにすべき
- **B4 連続日数も完了の手応えも無い。** 90日完走が商品なのに、続けた証が0%リングだけ
- **B5 リマインダーが無い。** iOS 16.4以降、ホーム画面に追加したPWAはWeb Pushが使える

### C. 情報設計・レイアウト

- **C1 ナビが三重。** 上に4タブ／Day画面の上に「前の日・Day選択・次の日」／下に「前・完了・次」
- **C2 ヘッダーが縦を約300px（画面の12%）食う。** 滅多に切り替えないタブが常時表示。モバイルの定石は下タブ
- **C3** Day画面は1本のスクロール。単語5→文法3→リスニング→テストが延々と続き、今どこで、あとどれだけかが分からない
- **C4** カードの入れ子が深く（カード＞カード＞カード）、枠線だらけで視線が迷う

### D. すぐ直せる粗

1. **ブックマークタブにDay画面の下ナビ（前・完了済み・次）が出ている。**
   `render()` が `bottomNav` を表示してから bookmark で早期リターンしているため。
   押すと関係ないDayの完了状態が変わる。実質バグ
2. 受験予定日が `mm/dd/yyyy` のまま（`<input type="date">` のロケール未指定）
3. 初回起動の「スキップして始める」がボタン内で改行する
4. ブックマークでピンインが二重に出ている
5. 決済まわりが `alert()`。アプリ内トースト（`hsk-toast`）があるのに使っていない

## 2. 3つの案と進める順番

| 案 | 中身 | 狙い | 規模 | リスク |
|---|---|---|---|---|
| **A 一画面一動作** | ナビ・情報の優先順位・学習のステップ化 | 迷いどころを消す。触れる状態にする | 小 | 小（CSSと描画の並べ替えが中心。SRS・データ構造は無傷） |
| **C 有料商品として見せる** | 価格画面・無料の区切り・復元導線 | 見ないまま決済画面に飛ぶ現状をやめる | 中 | 中（Worker/Stripe側も少し触る） |
| **B 習慣ドリブン** | ストリーク・通知・週次サマリー | 90日完走率を上げ、口コミと再訪を作る | 大 | 中（表示層を大きく作り替え。SWにpush追加） |

**A → C → B の順。** Aをやらないと、Cで作る価格画面もノイズの中に埋もれる。
Cは売上に直結し、Bは売れ始めてから効く。
今回のモックは **AとC**。Bは完了画面だけ先に受け皿として作ってある。

## 5. 案B — 今回はモックしていない

売れ始めてから着手する想定。完了画面（案Aで作る）がその受け皿になる。

- ホームを「今日の1枚」＋連続日数＋今週のカレンダーに寄せる
- 完了時の演出と週次サマリー
- **Web Push でリマインダー**（ホーム画面に追加したPWA向け。`sw.js` に push を足す）
- 学習を途切れないセッションとして流す（カードを送って進む）
- ストリークが途切れたときの体験も設計が要る（B4を入れるなら同時に考えること）

## 6. 実装するときの注意

- 画面遷移は必ず `goView()` を通す（`currentView` 1つで持つ設計）。新しい画面（完了・価格）も値を足して同じ経路に乗せる
- `LESSONS.length` ではなく `TOTAL_DAYS`（固定90）を使う。未購入だとDay8-90は存在しない
- 色は `:root` の既存トークンだけ。セージ／アプリコット／ブラッシュの3色で足りないか先に考える
- 丸ゴシック（Zen Maru Gothic）は見出し・ボタン・数字だけ。読ませる文章は Zen Kaku Gothic New
- **下タブへの変更は `tests/nav-test.mjs` が落ちる**（`.nav-tab` が4つあることを見ている）。テストも同時に直すこと
- 変更したら `node tests/run.mjs` を必ず通す

## 7. まだ決まっていないこと

1. **単語を1語ずつめくる形にするか。** いまの「5語を一覧」から変わるので好みが分かれる
2. **完了後に次のDayへ進ませない**設計にしている（1日1Dayが商品の形なので）。まとめて進めたい人向けの抜け道を残すか
3. **価格画面の比較表の項目。** いまは6行。増やすか減らすか
4. **ストリークを入れるか。** 入れると「途切れた」ときの体験も設計が要る

## 8. デザインの方向（`design/directions.html`）

構造（案A）は固定したまま、**視覚言語だけ**を4通り作って並べてあります。
画面は「今日」「学習（単語）」「完了」の3つで切り替えられます。

### いまの視覚言語で効いていないこと（コードから数えた事実）

| 見つけたこと | なぜ問題か |
|---|---|
| 角丸が**8種類**（999/20/18/16/14/12/10/8/6/3px） | 規則がなく、要素の格が伝わらない |
| 影が**6種類**、色もバラバラ（`rgba(16,24,40)` `rgba(20,30,50)` `rgba(46,75,107)` `rgba(0,0,0)`） | 青みの影が紙の暖色と喧嘩している |
| **すべてのカードに1.5pxの黒枠**、それが2〜3重 | 階層が作れず、大きさでしか重要度を示せない |
| 淡色3色が**装飾と意味を兼ねている** | 同じ色が「飾り」と「正解」の両方を指す |
| UIに**絵文字**（🔒 🔁 🎉 🔍 ★☆） | 端末ごとに字形が変わり、ブランドが崩れる |
| **ダークモード未対応**（`prefers-color-scheme` 0件） | 夜と移動中に開く商品なのに白い紙が光る |

そのうえで最大の論点は、**主ターゲット（仕事で中国語を使う大人）と ¥4,800 という価格に対して、
丸ゴシック＋手書き＋有機的シェイプ＋太い黒枠という register が「ゆるい手作りノート」に寄りすぎている**こと。

### 4つの方向

| | 考え方 | Pros | Cons |
|---|---|---|---|
| **方向1 いまを磨く** | 路線は変えず、枠線を減らして階層をつける | ブランドの連続性／**販促素材がそのまま使える**／CSSだけでリスク最小 | 「ゆるい」印象は残る／密度は上がらない／価格の説得力は上がりきらない |
| **方向2 静かな大人向け** | 装飾を削ぎ、密度を上げる。黒枠廃止・角丸14px・丸ゴシックは見出しと数字だけ・ダークモード | **主ターゲットに合う**／価格の説得力／夜に強い／スクショが締まる | ブランド名「加油＝応援」の世界観から一歩離れる／**販促素材の端末画面は撮り直し**／他社と似るリスク |
| **方向3 中文を主役に** | UIを透明にし、漢字の組版に投資（34px→46px・字間） | **学習アプリとしての説得力が最も高い**／読みやすさがそのまま価値／飽きない | 冷たい／差別化が弱まる／**90日続ける動機の演出がしにくい**／販促素材は全面作り直し |
| **推奨** | 方向2をベースに、中文は方向3の組版。**達成の瞬間だけ**方向1の温かさを集中投下 | 日常は静かで読みやすく、続ける動機は完了画面に集約できる | 方向2と同じ撮り直しコスト |

**推奨の考え方**：差別化はUIの装飾ではなく中身（日本人が間違えやすい点・AI添削）で取る。
90日続けさせるための演出は捨てないが、毎日見る画面には持ち込まず、完了・ストリーク・完走の一点に集中させる。
※「今日」画面では**方向2と推奨は同じ見た目**になります。違いが出るのは「学習」（中文の大きさ）と「完了」（温度）です。

### 方向を選んでも選ばなくても直すもの

1. 角丸を8種類 → 4段階（8 / 14 / 20 / 999）に統一
2. 影を1系統に（墨 `#2A2724` から作る。青い影をやめる）
3. UIの絵文字を**SVGの線アイコン**へ
4. **ダークモード対応**
5. 正誤の ○×✓✗ もアイコン化

## 9. 大胆な方向3案（`design/directions-bold.html`）

いまの世界観（紙・丸ゴシック・手書き）を一度捨てて考えたもの。
構造は同じで、**それぞれ「何で人を動かすか」の賭けが違う**。比較用に前回の推奨案を左端に置いてある。

| | 賭けどころ | 見た目の芯 | ◎ | △ |
|---|---|---|---|---|
| **案X 辞書・新聞** | **権威と信頼で買わせる** | 明朝（Noto Serif JP）＋**宋体**。罫線だけで組み、カードも角丸も影もゼロ。色は墨＋朱の2色。完了は朱の角印 | アプリで明朝はほぼ無く、圧倒的に差別化できる。**文法222項目のような文字量の多い中身に最適**。¥4,800の説得力が最も高い | 明朝は小さいサイズ・低輝度で可読性が落ちる。「堅い・古い」と感じる層がいる。日中2書体ぶんの読み込みが重い |
| **案Y 計器・ダッシュボード** | **進捗の可視化で続けさせる** | ダーク（`#0F1214`）が既定。数字は等幅、週の帯はヒートマップの升目。色は琥珀1色＋達成の緑。完了は祝う印を持たず数値だけ | 夜と移動中に強い。**ストリークと正答率が主役**になるので継続に直結。ダーク前提で二重管理がいらない | 語学の「温度」が消え、つまずいた日に冷たい。主ターゲット（駐在の営業・管理職）がこの記号を好むとは限らない |
| **案Z 切符・スタンプ帳** | **集めたくなる気持ちで続けさせる** | 濃紺×朱×生成り。カード＝半券でミシン目と整理番号。影ではなく**版ずれ**で立体に。週は押印、完了は二重丸の朱印 | **90日＝90枚という物語が継続動機に直結**。出張・渡航という文脈と噛み合う。ストアやSNSで目立つ | 装飾が強く毎日見ると飽きる恐れ。文法解説のような長文と相性が悪い。作り込みを外すとチープに転ぶ |

### 選ぶときの見立て

- **中身（文法222項目の解説・AI添削）を売りにするなら案X。**文字を読ませる商品との相性が最も良い
- **継続率を上げたいなら案YかZ。**ただしYは「計測が好きな人」、Zは「集めるのが好きな人」と、刺さる層が違う
- **案Zは「加油＝応援」というブランド名とも噛み合う**が、90日ぶんのスタンプ意匠を作り込む体力が要る
- どれも**販促素材（App Store 7枚・LP）は作り直し**になる。ただし版下は流用でき、`capture-app.mjs` の再実行が中心

## 10. デザインの洗練（`design/refined.html`）

方向を選んだあと、**craft の水準を上げるために何をするか**を前後で並べたもの。
推奨案と案X（辞書）の2方向に、同じ8つの処理をかけている。構造は変えていない。

| | 処理 | 中身 |
|---|---|---|
| 1 | **タイプスケールを固定** | 10/10.5/11/11.5/12/12.5/14/15/16/18/25px と刻んでいたのを **11 / 12.5 / 14 / 16 / 20 / 34** の6段だけに。段が少ないほど格の違いが読める |
| 2 | **4pxグリッドに乗せる** | 6/7/9/11/13px の混在を 8 / 12 / 16 / 20 に統一。画面端の余白も 14 → 16px |
| 3 | **数字を主役にする** | 「Day 13」を同じ25pxで並べるのをやめ、**Day=15px / 13=34px** に |
| 4 | **色を1つ減らす** | 「あたらしく覚える」の緑をやめ、色はブランド1色（今日の印）と墨だけに |
| 5 | **下端に「地面」を作る** | 週の帯と進捗を画面下へ寄せる。以前は下が空いて未完成に見えていた |
| 6 | **囲いを外す** | 例文の背景色の箱をやめて1本の細罫に。副次カードの説明文を削り数字だけに |
| 7 | **中文とピンインの対比** | 漢字を 46→52px（案Xは56px）、ピンインは小さく**字間を広げて**従属させる |
| 8 | **影を消し、罫を2階層に** | カードの影をやめ地との明度差だけで浮かせる。線は「細罫」と「太罫」の2種類だけ |

この8つは**どの方向を選んでも同じように効く**ので、方向の決定を待たずに合意しておける部分。

## 11. 案Xで進める（`design/x-next.html`）

**方向は案X（辞書・新聞）の洗練後に決定。** 次の2つを置いてある。

### アプリアイコンの候補6案

ホーム画面では60px前後でしか見えないので、**小さいサイズでの読みやすさ**が選定基準。
各案を 120 / 56 / 28px の3サイズと、ホーム画面に並べた状態で確認できる。

| | 案 | ◎ | △ |
|---|---|---|---|
| 1 | **朱印「油」** | 辞書・新聞の世界観に完全一致。小さくても形が残る | 「油」単体だと意味が伝わりにくい |
| 2 | **朱印「加油」** | 名前が一目で出る。印章として最も正統 | 60pxで2文字は潰れやすい |

### 今日画面の改善

「復習・模試が押せると分からない」「進捗が進捗に見えない」の2点を直したもの。

- **2列の罫組みをやめ、行（リスト）にした。**右端に罫で囲んだ「復習する」「受ける」を置いて押せることを明示。数字は左に残して一覧性を保つ
- **90日を90マスの格子にした。**原稿用紙の升目。完了＝墨のベタ、今日＝朱、これから＝空マス。1本のバーより「残りの量」が体感できる
- **「12 / 90」を30pxで置いた。**以前は11pxの脚注だった。進捗は脚注ではなく見出し
- **週の帯をやめた。**90マスが週も月も含んでいるので、週だけを別に出す必要がない
- 進捗の塊を太罫で区切って画面下端に固定。上＝今日やること／下＝これまで、と役割が分かれる
